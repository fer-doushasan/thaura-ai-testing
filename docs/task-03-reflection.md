# Task 03 — AI & Software Testing Reflection

### 1. How will AI impact software testing in the next 2–3 years?

I think the biggest shift won't be "AI replaces testers," it'll be AI collapsing the time between *having a test idea* and *having evidence*. Right now a lot of QA time goes into the mechanical part — writing the Playwright boilerplate, generating edge-case fixtures, parsing network logs, drafting the bug report — rather than the actual judgment part: deciding what's worth testing and what a given result actually means. Over the next 2–3 years I expect that mechanical layer to keep shrinking. Exploratory testing sessions will increasingly look like a tester describing intent in plain language and an AI agent driving the browser/API, capturing evidence, and coming back with a structured first draft of findings — which is close to how I worked through this assessment.

What won't go away is the judgment layer: deciding whether a decremented quota counter after a dropped connection is a bug or a resumable-turn feature, deciding whether a long-lived cookie is a real security issue or just a product choice, deciding when a "leak" your own automation flagged is actually a false positive from a bad selector. AI is good at generating volume and catching mechanical inconsistencies; it's still bad at knowing when *not* to escalate something, and at holding itself to "don't fabricate a result you didn't actually observe." That discipline is exactly where a human tester's value moves to. I'd also expect more AI involvement in triage/classification (bug vs. observation vs. security observation) and in keeping test evidence and reports in sync with a fast-moving codebase, since that's a place humans currently fall behind simply from volume.

### 2. Do you personally use AI? Does AI help you in testing? If yes, in what specific ways does it help?

Yes — I use it daily, and for this assessment specifically it was the primary tool I worked through everything with, not an occasional assist. Concretely, on this exact assessment: I used an AI coding agent (Claude Code) to write and iterate on the Playwright automation for almost every test area — the OTP/login flow, the 5-message quota exhaustion test, the file-upload matrix (valid/empty/corrupted/password-protected/oversized), the memory/incognito probes, and the direct API validation batch (missing fields, invalid model, legacy `functions` params, boundary payloads). It also helped me debug a real automation bug mid-session: an "incognito toggle" click was silently failing because it targeted a screen-reader-only `<span>` instead of its parent button, and an overly broad `.catch()` was swallowing the resulting timeout — the AI helped me pull the actual DOM structure, spot the mismatch, and fix the selector rather than me manually inspecting minified HTML.

I also used it for test-data generation (deterministic PDF/XLSX/PNG fixtures with known embedded markers, so extraction accuracy could be verified exactly rather than eyeballed), for analyzing raw API/network JSON at volume (e.g., correlating `rate-limit/check` responses against message sends to prove quota is enforced server-side, not just in the UI), and for drafting the structured write-ups (gap analysis tables, bug report fields) from that raw evidence so I could focus on reviewing and correcting the classification rather than formatting.

### 3. Which AI tools do you currently use (for testing or otherwise)?

Claude Code (Anthropic) is the one AI tool I actually use, day to day and not just for testing — it's how I worked through this entire assessment, from writing and running the Playwright/Node automation to reviewing raw evidence and drafting the write-ups. I don't split my usage across multiple AI tools; I'd rather go deep on one agentic tool I trust than juggle several for overlapping jobs. Alongside it I used standard non-AI QA tooling for the parts that don't need a model in the loop: Lighthouse for performance/SEO/accessibility scoring and JMeter for baseline load testing — listed here for completeness, not counted as "AI tools," since the value they add is deterministic measurement, not reasoning.

### 4. Which AI testing tool has been most helpful and why?

Claude Code, specifically for the *agentic* part rather than just code completion. The most helpful pattern wasn't "generate a test script" in isolation — it was the loop of: run a probe, look at the actual response/DOM, notice something inconsistent (like a false-positive "leak" caused by a selector capturing the wrong element, or a chat-quota test result that only makes sense once you realize the backend has resumable streaming turns), and revise the next test based on that, all within one continuous session instead of me manually round-tripping between a script, a browser, and my notes. For an assessment like this one, where a lot of the real findings come from noticing when your own tooling is misleading you, having the same agent write the probe, read the raw output, and flag the discrepancy in one pass was more valuable than any single generated test case.
